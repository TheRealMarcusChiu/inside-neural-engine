Inside the Neural Engine

Apple silicon puts several kinds of processor beside one shared pool of memory. This exhibit shows what the Apple Neural Engine (ANE) is for, how a tiny neural network turns pixels into scores, and why software, not the chip alone, decides where that math runs.

The ANE is specialized hardware for machine-learning inference. It is not another name for the CPU or GPU, and both of those can run neural networks too.

Explore the processors

Source: Apple Machine Learning Research, Deploying Transformers on the Apple Neural Engine

Three processors, three ways of working

The same neural-network math can run on the CPU, the GPU or the Neural Engine. What differs is the style of work each is built for. Pick a workload to see how the jobs might divide.

Photo tagging: the CPU decodes and resizes the photo, the GPU can push many pixel tiles through one filter at once, and the Neural Engine can run the supported layers of a Core ML vision model.

No processor wins by default. Actual placement depends on the model, the framework, the operations involved and the allowed compute units.

A neural network, one step at a time

Inference means running an already-trained model on new input. Here a deliberately tiny network scores a four-pixel image. Every number below is computed in your browser from the same formulas.

  1. Input. Four pixel intensities: 100, 50, 25, 100.
  2. Preprocessing. Divide by 100: X = [[1.00, 0.50], [0.25, 1.00]].
  3. Neural layers. Multiply by weights W = [[0.80, −0.40], [0.20, 0.90]], apply ReLU (max(0, x)), then average each column: [0.65, 0.43].
  4. Output scores. Multiply by a readout matrix and apply softmax: Diagonal 0.43, Bar 0.27, Other 0.29.

Each hidden value is one row of X times one column of W: multiply matching pairs, then add. Choose an output cell.

Core ML decides, within limits you set

Apps that use Core ML can name which compute units a model is allowed to use. That setting is a permission, not a placement order. With .all, the system picks the best available unit, which can include the Neural Engine.

Every operation is supported, and .all lets Core ML choose among the CPU, the GPU and the Neural Engine.

One pool of memory, fewer copies

On Apple silicon, the CPU, GPU and other units share one pool of memory, so data doesn't need to be duplicated into a separate graphics memory first. Sharing reduces explicit copies. It doesn't remove synchronization, bandwidth limits or format conversions.

Weights, activations and outputs live in one pool. Each unit reads the same data, but work that depends on another unit's result still has to wait for it to finish.

Sources: Apple Newsroom, M1 announcement (2020), MLX: unified memory

Running a language model on your Mac

"An AI app" doesn't automatically mean "uses the Neural Engine." Three layers get confused: MLX is software, Metal is Apple's GPU graphics and compute API, and the Neural Engine is hardware.

MLX is an array framework whose documented devices on Apple silicon are the CPU and the GPU; GPU work goes through Metal. MLX-LM builds text generation and fine-tuning on top of it, so loading a Qwen model with MLX-LM is a practical local example, but it is not a Neural Engine path. oMLX serves models using MLX and MLX-LM; its README also describes an optional separate Metal engine.

Placement: Eligible for specialized placement

  • Batching more requests together still finds idle parallel lanes, so combined throughput can rise.
  • The model uses operations a specialized unit supports, so Core ML has the option to place them there. That is an opportunity, not a guaranteed speedup.

What to remember

  1. The Neural Engine is specialized inference hardware. The CPU and GPU run neural networks too.
  2. A forward pass is mostly matrix multiplication plus simple functions like ReLU and softmax.
  3. Core ML compute units are a permission. The system chooses within them, and unsupported operations aren't made compatible by asking.
  4. Unified memory removes many copies, not synchronization or bandwidth limits.
  5. MLX and llama.cpp's Metal build use the CPU and GPU. Core ML is the route that can reach the Neural Engine.

Glossary

NPU / ANE
Neural processing unit: hardware specialized for neural-network math. ANE is Apple's, the Apple Neural Engine.
Inference
Running an already-trained model on new input to get an output.
Tensor
A grid of numbers with any number of dimensions. A matrix is a two-dimensional tensor.
More on tensors

An image batch is often a four-dimensional tensor: images × channels × height × width. The toy network here uses 2×2 matrices so every value stays visible.

Matrix multiplication
Each output cell is a row of one matrix times a column of the other: multiply pairs, then add.
Why it dominates

Dense layers, attention and (after rearrangement) convolutions all reduce to many multiply-and-add steps, which is why hardware specializes for them.

Model weights
The learned numbers a model multiplies its input by. Here they were picked by hand for teaching.
Activations
Intermediate values produced as input flows through layers, like the hidden matrix above.
Quantization
Storing weights or activations with fewer bits, which trades a little precision for less memory and data movement.
A caution

How much quality changes depends on the model and the method. It is a trade-off to test, not a free win.

Unified memory
One pool of memory shared by the CPU, GPU and other units on Apple silicon, reducing explicit copies.
Core ML
Apple's framework for running models in apps, which can use the CPU, GPU and Neural Engine.
MLX
An open-source array framework for machine learning; on Apple silicon its documented devices are the CPU and GPU.
Metal
Apple's low-level API for GPU graphics and compute. Metal targets the GPU, not the Neural Engine.
